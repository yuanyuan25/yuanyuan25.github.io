先分清三个问题：参数量是在数模型里有多少个可学习的数；显存是在数某个时刻要保存多少字节；计算量是在数处理数据时执行多少运算。它们有关联，但不能互相替代。本文按“矩阵形状 → 元素个数 → 字节或运算次数”逐项计算；GB 使用 10910^9109 字节，GiB 使用 2302^{30}230 字节。

2. 模型参数量

一个 decoder 模型通常包括：输入 embedding、重复 LLL 次的 Transformer block、末端归一化、输出词表头。先算清一个 block 中 Attention、MLP 和归一化各有多少参数，再乘层数，最后加只出现一次的词表层等部分。是否共享参数、是否带偏置，要按具体配置决定。

2.1 Attention

对于输入宽度 HinH_{\rm in}Hin​、输出宽度 HoutH_{\rm out}Hout​ 的线性投影 Y=XW+bY=XW+bY=XW+b，每个输出特征都需要对全部输入特征加权，因此 WWW 有 HinHoutH_{\rm in}H_{\rm out}Hin​Hout​ 个参数；如果启用偏置 bbb，还要加 HoutH_{\rm out}Hout​ 个。这里用数学上的 XWXWXW 记号，PyTorch 存储权重时可能转置，但元素数不变。

2.2 MLP、归一化、词表层

对于普通两层 MLP，第一层把每个 token 从宽度 HHH 映射到 III，因此有 HIHIHI 个权重和 III 个偏置；第二层从 III 映射回 HHH，因此有 IHIHIH 个权重和 HHH 个偏置。把两层相加：

PMLP=HI+I⏟H→I+IH+H⏟I→H=2HI+I+H.\begin{aligned} P_{\rm MLP} &=\underbrace{HI+I}_{H\to I}+\underbrace{IH+H}_{I\to H}\\ &=2HI+I+H. \end{aligned}PMLP​​=H→IHI+I​​+I→HIH+H​​=2HI+I+H.​

SwiGLU 则有 gate 与 up 两条从 HHH 到 III 的投影，再由 down 从 III 回到 HHH。三组矩阵都要训练；忽略偏置时：

PSwiGLU=HI⏟gate+HI⏟up+IH⏟down=3HI.\begin{aligned} P_{\rm SwiGLU} &=\underbrace{HI}_{\rm gate}+\underbrace{HI}_{\rm up}+\underbrace{IH}_{\rm down}\\ &=3HI. \end{aligned}PSwiGLU​​=gateHI​​+upHI​​+downIH​​=3HI.​

标准 affine LayerNorm 通常有 gamma、beta 两组参数，每层 2H2H2H；Qwen 使用只有 scale 的 RMSNorm，每层 HHH。一个 Qwen block 内两次 RMSNorm 共 2H2H2H，此外整个 decoder 还有 final RMSNorm。

embedding 为 VHVHVH；只有配置确实共享 input embedding 与 lm_head 时才只计一份。未共享时，两个矩阵合计 2VH2VH2VH。

3. 训练显存

3.1 模型状态与峰值

模型状态包括参数本身、反向得到的参数梯度，以及优化器为了下一次更新而保存的信息。它们主要随参数量 PPP 增长；前向激活和临时工作区则还受 batch、序列长度和内核实现影响。

以低精度权重/梯度、FP32 主权重与 Adam 状态的传统配置为例：每个参数有一份 2 byte 计算权重、一份 2 byte 梯度，以及三份 4 byte 状态。所以先算每参数的字节数，再乘参数量：

Mstates=P(2+2+4+4+4)=16P bytes.\begin{aligned} M_{\rm states} &=P(2+2+4+4+4)\\ &=16P\ \text{bytes}. \end{aligned}Mstates​​=P(2+2+4+4+4)=16P bytes.​

上式五项依次是：低精度计算权重 2P2P2P、低精度梯度 2P2P2P、FP32 主权重 4P4P4P、Adam 一阶矩 4P4P4P、二阶矩 4P4P4P。这里暂时只统计模型状态，不含激活。

例如按教学用 P=7×109P=7\times10^9P=7×109 计算，状态为 112GB，约 104.31GiB。实际 Qwen 参数量更大；训练峰值还需加上激活、通信和临时缓冲。梯度 dtype、AMP、优化器、分片会改变系数，详见混合精度。

3.2 教学版激活估算

下面公式针对保存反向所需激活、普通 MHA、两层 I=4HI=4HI=4H MLP、LayerNorm、启用相应 dropout、未用 FlashAttention 和重计算的教学模型。假设保存的主要激活为 2 bytes，dropout mask 为 1 byte；不能把任意 int 或 attention mask 都当成 1 byte。

激活显存为什么会大：前向算过的张量，反向求导时还可能要用，因此不能全部立即释放。例如线性层的权重梯度需要它的输入，softmax 的梯度可以由其输出计算。下面列的是为反向保留下来的对象，不是把前向出现过的所有变量都重复相加。

先展开 Attention 的每一项。 一个 token 表示张量有 b×s×Hb\times s\times Hb×s×H 个元素，按 2 byte 保存就是 2bsH2bsH2bsH。而每个 head 的注意力权重有 s×ss\times ss×s 个位置对，共 bnqbn_qbnq​ 个 head，因此有 bnqs2bn_qs^2bnq​s2 个元素。这两类形状分别产生下面的一次项与序列长度二次项：

这个 eager 实现显式生成 attention weights，并在 softmax 中使用 FP32，还可能重复 KV 头。实际估算要跟踪各张量的 dtype、存储共享和存活时间，不能只按同一套 2 byte 假设计数。

4. 推理与 KV cache

推理不需要保存用于反向的全套激活和优化器状态，但仍有前向激活与临时 workspace，尤其 prefill 阶段不能忽略峰值。

4.1 为什么只缓存 K/V

考虑正在生成回答的因果 self-attention。位置 ttt 的 query 向量记为 qtq_tqt​，历史位置 jjj 的 key、value 分别记为 kj,vjk_j,v_jkj​,vj​，每个头的维度为 ddd。由于位置 ttt 只能看到自己和前面的 token，可见范围是 j≤tj\le tj≤t。

我们定义 at,ja_{t,j}at,j​ 为位置 ttt 分配给位置 jjj 的注意力权重：先计算并缩放 query/key 点积，再对所有可见 key 做 softmax。该位置的输出 oto_tot​ 就是用这些权重对 value 求和：

at,j=exp⁡(qt⊤kj/d)∑u≤texp⁡(qt⊤ku/d),ot=∑j≤tat,jvj.\begin{aligned} a_{t,j} &=\frac{\exp(q_t^\top k_j/\sqrt d)}{\sum_{u\le t}\exp(q_t^\top k_u/\sqrt d)},\\[4pt] o_t &=\sum_{j\le t}a_{t,j}v_j. \end{aligned}at,j​ot​​=∑u≤t​exp(qt⊤​ku​/d​)exp(qt⊤​kj​/d​)​,=j≤t∑​at,j​vj​.​

把整段序列写成矩阵，再看新增位置。 以三个位置为例，令 AAA 为经过缩放、因果 mask、逐行 softmax 后的矩阵：

A=[a1100a21a220a31a32a33],O=AV=[a11v1a21v1+a22v2a31v1+a32v2+a33v3].\begin{aligned} A &=\begin{bmatrix} a_{11}&0&0\\ a_{21}&a_{22}&0\\ a_{31}&a_{32}&a_{33} \end{bmatrix},\\[4pt] O &=AV\\ &=\begin{bmatrix} a_{11}v_1\\ a_{21}v_1+a_{22}v_2\\ a_{31}v_1+a_{32}v_2+a_{33}v_3 \end{bmatrix}. \end{aligned}AO​=​a11​a21​a31​​0a22​a32​​00a33​​​,=AV=​a11​v1​a21​v1​+a22​v2​a31​v1​+a32​v2​+a33​v3​​​.​

矩阵的第 1 行只能使用 v1v_1v1​，第 2 行使用 v1,v2v_1,v_2v1​,v2​，第 3 行使用 v1,v2,v3v_1,v_2,v_3v1​,v2​,v3​。因果 mask 把右上角的未来位置权重置为 0；每一行的输出都是该行非零权重对应的 value 加权和。

在标准因果 self-attention 中追加位置 t+1t+1t+1 时，过去各行不会看到未来 token，因此既有位置的表示和 K/V 可复用。缓存更新为：

K1:t+1=[K1:t;kt+1],V1:t+1=[V1:t;vt+1],K_{1:t+1}=[K_{1:t};k_{t+1}],\qquad V_{1:t+1}=[V_{1:t};v_{t+1}],K1:t+1​=[K1:t​;kt+1​],V1:t+1​=[V1:t​;vt+1​],
ot+1=∑j=1t+1eqt+1⊤kj/d∑u=1t+1eqt+1⊤ku/d vj.o_{t+1}=\sum_{j=1}^{t+1} \frac{e^{q_{t+1}^\top k_j/\sqrt d}}{\sum_{u=1}^{t+1}e^{q_{t+1}^\top k_u/\sqrt d}}\,v_j.ot+1​=j=1∑t+1​∑u=1t+1​eqt+1⊤​ku​/d​eqt+1⊤​kj​/d​​vj​.

计算新增一行只出现新的 qt+1q_{t+1}qt+1​，但要用所有可见位置的 K/V；这就是保留历史 K/V 而无需保留历史 Q 的原因。

例如，prompt 的三个 token 首次前向后，可以缓存这三处在每一层的 K/V，并用最后位置的 logits 生成第 4 个 token。下一步将第 4 个 token 送入模型时，只计算这个新位置的 query 和 K/V，把新 K/V 追加到缓存，再用新 query 关注全部四个位置，产生预测第 5 个 token 的 logits。历史 query 不参与这次新输出，因此无需作为 KV cache 的一部分保留。

4.2 GQA/MQA 通用 KV 公式

假设 bbb 条序列都缓存 nnn 个 token，K/V 使用相同 head 数、head dimension 与每元素字节数 qqq：

MKV=2bLn nkvd q.M_{\rm KV}=2bLn\,n_{kv}d\,q.MKV​=2bLnnkv​dq.

按维度逐项相乘：每条序列、每层、每个 token 的 K 有 nkvdn_{kv}dnkv​d 个元素，V 同样多；乘上序列数 bbb、缓存长度 nnn、层数 LLL、每元素字节数 qqq，就是上式。若把长度拆为 prompt 长度 sss 和已经缓存的生成长度 ggg，则 n=s+gn=s+gn=s+g。注意这里计的是已经写入缓存的 token 数。

第一个 2 表示 K 和 V。若使用 MHA，则 nkvd=Hn_{kv}d=Hnkv​d=H；再取每元素 q=2q=2q=2 byte，就得到 4bLnH4bLnH4bLnH。使用 GQA 时要保留实际的 nkvn_{kv}nkv​，因为缓存宽度由 KV 头数决定。

MKV=2×1×28×2048×4×128×2=117440512 bytes=112 MiB.\begin{aligned} M_{\rm KV} &=2\times1\times28\times2048\times4\times128\times2\\ &=117440512\ \text{bytes}\\ &=112\ \text{MiB}. \end{aligned}MKV​​=2×1×28×2048×4×128×2=117440512 bytes=112 MiB.​

5. MoE 的显存

MoE 为某些层准备了多个专家，但每个 token 只选择其中一部分参与计算。即使某个专家本次没被选中，它的权重也仍需存放在某处；因此存储量主要看总参数量，每 token 的计算量才主要看激活参数量。

定义 PsharedP_{\rm shared}Pshared​ 为共享层参数量，EEE 为专家数，PexpertP_{\rm expert}Pexpert​ 为每个专家参数量，ProuterP_{\rm router}Prouter​ 为路由器参数量，qqq 为每个权重的存储字节数。假设各专家大小相同，仅权重存储就是：

Mweights≈q(Pshared+EPexpert+Prouter).M_{\rm weights}\approx q(P_{\rm shared}+E P_{\rm expert}+P_{\rm router}).Mweights​≈q(Pshared​+EPexpert​+Prouter​).

“MLP 参数量乘专家数”只覆盖专家部分。以名称近似表示的 30B-A3B 为例，30B 总参数的 BF16 权重约 60GB；这不是训练总显存，也不是单卡必然占用。EP/TP 可以分片存储。

训练仍需保存或重计算激活；推理也有 expert dispatch/combine、路由和临时激活的峰值。计算完释放只缩短存活时间，不代表显存可忽略。

6. FLOPs 与训练时间

6.1 矩阵乘法

设左矩阵形状为 [m,n][m,n][m,n]，右矩阵为 [n,p][n,p][n,p]，输出共有 mpmpmp 个元素。每个输出元素都是长度为 nnn 的点积；把“每个点积的运算量”乘以“输出元素个数”，得到：

FLOPs⁡([m,n]×[n,p])≈2mnp.\operatorname{FLOPs}([m,n]\times[n,p])\approx2mnp.FLOPs([m,n]×[n,p])≈2mnp.

严格标量计数中每个输出有 nnn 次乘法、n−1n-1n−1 次加法；工程估算通常记作 2n2n2n。FLOPs 表示运算量，FLOP/s 表示吞吐。

6.2 普通 MHA + 两层 MLP

忽略归一化、激活、softmax 等相对较小的算子开销：

Fattn≈8bsH2+4bs2H,FMLP≈4bsHI.F_{\rm attn}\approx8bsH^2+4bs^2H, \qquad F_{\rm MLP}\approx4bsHI.Fattn​≈8bsH2+4bs2H,FMLP​≈4bsHI.

这里 FattnF_{\rm attn}Fattn​ 与 FMLPF_{\rm MLP}FMLP​ 分别表示一个 block 的 Attention、MLP 前向运算量。为了看清各项怎么组成它们，逐算子套用矩阵乘的 2mnp2mnp2mnp 计数：

GQA 改变投影部分；SwiGLU 的 MLP 投影约 6bsHI6bsHI6bsHI。长上下文的二次 attention 项和大词表输出项不能无条件省略。softmax 的具体 FLOPs 也取决于是否做稳定化及如何计数 exp/div，需要说明采用什么计数口径。

6.3 6PT 与重计算

这里 PPP 表示参与密集计算的参数量，TTT 是整个训练过程累计处理的 token 数，不是单条序列长度。在大矩阵线性层占主导时，每个 token 使用每个权重完成一次乘法和一次累加，前向大约需要 2P2P2P 次运算。把全部训练 token 的前向与反向加起来，常用近似是：

Ftrain≈6PT.F_{\rm train}\approx6PT.Ftrain​≈6PT.

系数 6 的来历： 对线性层 Y=XWY=XWY=XW，前向一次矩阵乘；反向需要分别计算输入梯度 GX=GYW⊤G_X=G_YW^\topGX​=GY​W⊤ 和参数梯度 GW=X⊤GYG_W=X^\top G_YGW​=X⊤GY​，各一次形状对应的矩阵乘。三者 FLOPs 同阶：

Fforward≈2PT,Fbackward≈2Fforward≈4PT,F_{\rm forward}\approx2PT,\qquad F_{\rm backward}\approx2F_{\rm forward}\approx4PT,Fforward​≈2PT,Fbackward​≈2Fforward​≈4PT,
Ftrain≈(1+2)×2PT=6PT.F_{\rm train}\approx(1+2)\times2PT=6PT.Ftrain​≈(1+2)×2PT=6PT.

这是线性投影占主导时的近似；并非所有算子的反向都严格是前向两倍。全量再做一次相同前向时，才增加 2PT2PT2PT：

Ftrain,recompute≈(1+2+1)×2PT=8PT.F_{\rm train,recompute}\approx(1+2+1)\times2PT=8PT.Ftrain,recompute​≈(1+2+1)×2PT=8PT.

若所有相关前向计算都额外重做一次，可粗略改成 8PT8PT8PT；选择性重计算的增量更小，不能一律写成 8。MoE 也不能直接把总参数数目代进密集模型公式。

按教学用 P=7×109,T=300×109P=7\times10^9,T=300\times10^9P=7×109,T=300×109：无重计算约 1.26×10221.26\times10^{22}1.26×1022 FLOPs，全量前向重计算近似约 1.68×10221.68\times10^{22}1.68×1022 FLOPs。

6.4 时间估计的效率口径

训练时间可以粗略写成“总运算量 ÷ 集群每秒真正完成的运算量”。定义 FexecutedF_{\rm executed}Fexecuted​ 为包含重计算在内的实际运算总量，NGPUN_{\rm GPU}NGPU​ 为 GPU 数，FpeakF_{\rm peak}Fpeak​ 为单卡在选定精度下的峰值 FLOP/s，再用效率 ηexecuted\eta_{\rm executed}ηexecuted​ 折算有效吞吐：

t≈FexecutedNGPUFpeakηexecuted.t\approx\frac{F_{\rm executed}}{N_{\rm GPU}F_{\rm peak}\eta_{\rm executed}}.t≈NGPU​Fpeak​ηexecuted​Fexecuted​​.

ηexecuted\eta_{\rm executed}ηexecuted​ 是实际执行 FLOPs 相对峰值的有效比例，包含重计算时接近 HFU 口径；不是监控面板的 GPU busy 百分比。若采用按模型有效 FLOPs 定义的 MFU，就应匹配其分子，避免同时加重计算又用已扣除重计算的效率重复惩罚。

使用前面全量前向重计算的 8PT8PT8PT 近似。假设 64 张 A100、每卡 FP16/BF16 dense 峰值 312TFLOP/s、执行效率 0.45：

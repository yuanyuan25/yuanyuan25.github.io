TeleChat to Xing4: Advancing Frontier Agentic Models on Domestic Chips and Frameworks
🔴 重点精读 📅 2026-11-17 🏢 Xingchen AGI Lab（TeleChat 团队） Agentic 国产算力 MoE 长上下文 Infra Agentic arXiv:2611.22115 HF 👍 167
创新点
系统公开在国产 Ascend 芯片 + MindSpore 框架上训练 frontier agentic 模型的全栈工程报告。架构侧组合 MLA+DSA+IndexShare 长上下文注意力、宽浅 MoE 拓扑、DSpark 块级投机解码；系统侧基于 MindSpore HyperParallel 实现 HSDP（完全去除流水线并行）、owner-based Muon 分布式优化器、细粒度选择性重计算、CPU 亲和与核隔离；后训练侧提出 TeleGym 统一 agent 执行平台（异步执行 + 有界过采样 + 部分 rollout）。开源 29B-A4B 成员（原生 256K 上下文）。
结论
在 8192 张 Ascend 910C 上完成 285B（激活 17B、支持 1M 上下文）预训练；MLA+DSA+IndexShare 使 prefill 吞吐达纯 MLA 基线的 4.68 倍；DSpark 带来 2.67–3.77 倍解码吞吐；宽浅拓扑额外提升约 10% 训练吞吐，消除流水线并行再提 16.1%。
结论支撑
架构对比基于华为 Zhanlu 模拟框架（TTFT/TPOT/吞吐三指标，32 卡 P/D 分离部署）；DSpark 在 GSM8K/MATH-500/HumanEval 等六个基准实测吞吐；训练优化在 1024 卡 profiling 集群上分别实测降步时 9.1%/6.9%/15.2%。对照配置清晰，但部分架构结论来自模拟器而非端到端生产部署（论文已声明模拟可能偏乐观）。
局限性
模型能力榜单成绩着墨较少，agentic 效果有待后续释放验证；架构选型深度绑定 Ascend 硬件特性（Cube 强、Vector 与 HBM 受限），迁移到 GPU 需重新校准；模拟结果可能乐观。
点评与适用范围
国产算力训练团队必读：把“硬件特性→架构选择→并行/优化器/通信设计”串成完整方法论，285B@8192 卡的 HSDP 去 PP、Muon owner 执行等细节可直接借鉴；对 GPU 大团队，其按带宽拓扑设计并行策略的思路同样适用。落地难度中高，需要全栈掌控力。
InclusionMed: Benchmarking AI for Inclusive Healthcare
📅 2026-11-16 🏢 The InclusionMed Collaboration 评测基准 医疗 AI 诊断推理 Agentic arXiv:2611.21218 HF 👍 104
创新点
开放医疗 AI 评测倡议：InclusionMed Atlas 按 3 类医疗角色 × 3 种 AI 能力组织基准，从 388 个候选基准经结构化审计 + 独立复现选出 4 个公开基准，加上私有诊断推理基准 DxFiles，形成五基准 Atlas 与 InclusionMed Index 聚合分。
结论

结论支撑
388 候选结构化审计 + 独立复现 + 任务级 tag 的组内分析，工程可信度高；Index 按角色/能力双维分解。
局限性
9 个角色-能力单元只覆盖 3 个；私有基准无法外部复核；单次评测快照，未做多 seed 稳定性分析。
点评与适用范围
医疗 AI 应用方的选型参考框架——“按角色/能力/成本三维选型”的方法可推广到其他垂直行业评测。

SWE-CoWork: Benchmarking Coding Agents as Digital Employees in Organizations
📅 2026-11-15 Coding Agent 评测基准 软件工程 Agentic arXiv:2611.20218 HF 👍 53
创新点
把 coding agent 放进模拟工程组织：101 个真实仓库开发任务、11 语言、12 领域，26 个有职责边界、有限知识与受控协作行为的“同事”；agent 需从交接简报、同事与工作记录中恢复需求、调和冲突证据并交付通过私有可执行测试的实现。
结论
头部模型约通过 63% 的 fail-to-pass 测试但完整任务完成率不足 8%；直接给完整需求 F2P 提升约 16 个百分点而完整完成率不变；需求跟踪（澄清→实现→验证→交接）是核心瓶颈。

101 仓库大规模评测 + 需求级轨迹分析（如 Claude-Opus-5.5 首问 93% 指向责任人但仅获得 64% 的同事持有需求），失败归因细致。
局限性
模拟同事行为受控，与真实组织有差距；完整完成率度量严格，可能低估部分交付价值；私有测试存在过拟合测试的风险。
点评与适用范围
做 coding agent 产品化的团队应重视其结论：补齐需求管理与跟踪工具链比单纯提升代码生成能力更紧迫。
SPILLWAY: Separating Target Admission from Sanitization to Defend Tool-Using Agents against Prompt Injection
📅 2026-11-04 Agent 安全 提示注入 工具调用 Agentic arXiv:2611.07222 HF 👍 47
创新点
不依赖模型的确定性注入防御：利用工具返回的 typed 字段（发件人/收款账户）识别动作目标——目标值必须来自只读工具的 typed 字段或固定委托规则才放行；固定规则 sanitizer 先行移除指令性文本并保留证据，本地 judge 可恢复被拒调用但永不恢复目标位于已移除文本的调用。
结论
3 个骨干 × 7 任务套件下无标准模板注入能重定向动作；面对已发布的 RL 攻击者平均域内攻击成功率仅 0.007；达到该防线几乎不增加模型调用、无防御触发的重跑，且效用分最高。
结论支撑
跨骨干、多套件、学习型攻击者三重验证，指标含 NRP/ERS 复合分；伪造聊天模板直接归零。
局限性
仅覆盖“动作去向”单维度，数据泄露类风险不在范围；委托规则需人工维护；typed 字段假设依赖工具 API 设计。
点评与适用范围
个人 AI agent（邮件/文件/支付）安全落地的务实方案，“确定性地板 + 可审计拒绝”设计值得所有工具型 agent 借鉴，落地门槛低。
The Resolution Hypothesis: Agent Evolution's Key Is Identifying Improvements
🔴 重点精读 📅 2026-11-17 Agent 进化 RSI 评估方法 Agentic arXiv:2611.23068 HF 👍 39
创新点
提出 Resolution Hypothesis：agent 进化停滞的根因不是提案不够好，而是噪声评估无法可靠识别改进。在候选级（选择 artifact）与方法级（方法排名）两个层面验证：7 种进化方法 × 6 个模型，累计超 1000 万次 LLM 调用。
结论
候选层面——有益的候选 artifact 确实存在，但现有选择机制不优于随机，错误随轮次累积；方法层面——论文间典型几个百分点的差距小于同一方法两次独立运行的差异，已发表排名常靠运气。agent 进化的瓶颈是让真实改进可检测、可积累。
结论支撑
规模空前的受控实验（10M+ LLM calls），双层级证据链完整，统计论证扎实，是该领域少见的“元研究”。
局限性
结论限于“评估驱动”的进化范式；不同任务域的噪声水平可能不同；论文指出问题但未给出统一降噪方案。
点评与适用范围
所有做 RSI/self-improving agent 的团队必读：应把精力从“设计更好的提案器”转向“让改进可检测、可积累”；多 seed、置信区间的评测工程将成为核心竞争力。

点评与适用范围
做 agent 自我进化平台的团队可把 SIM 作为延续学习的默认组件——成本低、收益稳、易集成。

📅 2026-11-17 Weight-Space 架构设计 可解释性 基础架构创新 arXiv:2611.22055 HF 👍 59
创新点
研究无梯度场景下是否还需要 Transformer：给三个前沿 LLM 极少指导、10 个标注样本与沙箱，让它们写固定架构权重或自行设计架构（多选题为任务）；LLM 自发收敛到“把纯文本事实编译成稀疏表 + 固定查询过程”的方案；据此提出 associative-memory 模型。
结论
LLM 设计的查表模型以约 1/1800 的参数达到比同一 LLM 所写 Transformer 更高的测试精度（多选任务至多 54.4%）；可解释性远超梯度模型——每个错误可定位到单行、删行只影响约一个答案；同尺寸推理比 Transformer 快至多 17 倍；预训练 LLM 仍更准确，结论仅关于“写权重时该选什么结构”。
结论支撑
3 个 LLM × 多任务 × 生成式任务与预训练权重检验，现象跨模型一致。
局限性
任务限小样本选择题类，绝对精度低；与预训练范式的比较不对等；稀疏表结构的可扩展性未知。
点评与适用范围
weight-space programming 研究的必读启示：当监督来自 LLM 而非梯度时，架构先验应重新设计——对 test-time training 方向有启发。

创新点

结论

结论支撑

局限性

点评与适用范围

🔴 重点精读WHALE: A Simple Recipe for Joint Harness-Weight Optimization
arXiv:2609.00196
创新点
指出 agent 性能由模型权重与可执行 harness 代码（管理上下文与控制流）共同决定，单独优化任一者都会被冻结的另一方瓶颈。WHALE 提出交替优化：在当前 harness 下更新权重，再在更新后的模型下搜索更优 harness，分别用在线 rejection-sampling 微调与 Meta-Harness 实例化。何时切换阶段是关键设计——用固定阶段时长或基于训练信号的自适应 patience 规则区分真实改进与噪声。
结论
在 Qwen3.5-2B/4B agent 上跨三个域（搜索问答、数学推理、国际象棋谜题），WHALE 的 best mean@8 准确率比仅优化权重、仅优化 harness、以及 Fast-Slow Training 高 4.15–24.38 个百分点。瓶颈可能在任一端：SearchQA 中 harness 搜索用远少于权重训练的 rollout 就追平峰值，而数学域只有在权重更新后 harness 搜索才有效。小步交替也优于先训权重再搜 harness 的分阶段方案，且 rollout 成本更低。
结论支撑
在两个模型规模、三个差异较大的域上与四类对照方法比较，并给出"瓶颈不对称"的机理分析，实验设计对论点支持充分。mean@8 指标比单次结果稳健；但基座均为小模型（2B/4B），更大模型上的结论待验证。
局限性
仅验证到 4B 规模，harness 搜索空间由 Meta-Harness 定义，结论可能依赖搜索空间的表达能力；harness 改动带来的行为漂移与安全性问题未讨论；切换规则引入额外超参，敏感性分析有限。
点评与适用范围
做 agent 系统、agent RL、自动化 harness/scaffold 优化的团队应精读："权重-harness 交替优化"很可能成为 agent 训练的标准实践之一，且在小模型上即见效，成本门槛低。落地难度中等，rejection-sampling FT 与 harness 搜索均有开源代码可用。
推荐理由
首次系统化论证并验证了权重与 harness 联合交替优化的收益，直指当前 agent 训练"只调权重、冻结 scaffold"的普遍盲区，具备成为 agent 优化范式的潜力且代码开源。
Repo-To-Skill: Distilling GitHub Repositories Into AI4AI Skills
arXiv:2609.02749
创新点
提出将 GitHub 上 ML 仓库中的『操作性知识』（operational knowledge）蒸馏为紧凑、可验证、可复用的 skill，补齐了现有 research agent『有方法知识、缺落地 know-how』的空白层。蒸馏分 task-agnostic（离线从 1000 个常用仓库提炼出 5000+ 验证过的 skill，组成 AREX-Skill Library，覆盖 20 个领域 178 个能力族）和 task-oriented（按具体任务按需生成）两种互补形式。与 RAG 式检索原始文档不同，skill 是经过验证的可执行操作上下文。
结论
在 backbone（GPT-5.5）、harness 和下游执行预算完全固定的情况下，仅加入蒸馏 skill 就使研究 agent 在 MLE-bench 上提升 134.3%、PaperBench +34.4%、FrontierCS +9.2%、PassNet +14.0%。结论：agent 能力的很大一块增量来自外部操作知识的注入，而非模型本身。
结论支撑
采用严格控制变量的对照实验：固定模型、harness、执行预算，唯一变量是是否挂载 skill 库，在四个不同性质的研究类 benchmark 上评测，增益一致为正，说服力较强。AREX-Skill Library 规模（5000+ skill / 1000 仓库）也说明蒸馏流程具备可扩展性。
局限性
实验依赖单一 backbone（GPT-5.5），skill 对其他模型的迁移性未验证；skill 的『验证』标准和长期维护成本（仓库版本演进后 skill 失效）未详述；MLE-bench +134% 的超大增益可能部分源于基线 agent 本身较弱，绝对水平未给出。
点评与适用范围
对做 AI4Research / 自动化 ML 实验 agent 的团队价值很高：skill 蒸馏思路可直接嫁接到自有 harness 上。落地门槛中等——需要建 skill 验证管线，但比微调模型便宜得多，是『不改模型改上下文』路线的代表性工作。
Terminal-Universe: Turning Agent Trajectories into Scalable Terminal Environments
arXiv:2609.04148
创新点
核心洞察：轨迹中的工具执行历史暴露了其所运行环境的结构和内容，因此可以从轨迹反向重建可执行环境，而不是从零生成环境。框架重放文件操作还原 agent 修改前的工作区，由 completion agent 补齐缺失文件与依赖，再在其上重建原任务并沿广度（挖掘环境间依赖、合成跨工作区查询）和深度（user agent 驱动的多轮会话）两个轴扩展任务。
结论
从公开 terminal agent 轨迹产出 37.3k 个任务完备环境。用该语料 SFT Qwen3.5-27B，Terminal-Bench 2.1 单轮提升 11.9 分，EvoCode-Bench v2 MT@4 多轮提升 13.8 分。结论：环境是比轨迹更本质的训练资产——一个环境可反复查询出大量可验证任务并提供执行反馈。
结论支撑
把『轨迹→环境→新任务』全链路打通并用下游 SFT 增益验证，实验闭环完整；广度/深度两个扩展轴对应真实开发中跨仓库和多轮交互两个痛点，设计动机清晰。37.3k 环境规模也证明方法可扩展。
局限性
重建环境依赖 completion agent 补齐文件，补全错误会引入噪声标签，环境保真度未单独量化评估；只验证了 SFT 路径，未在 RL 设定下验证环境作为交互反馈源的价值（而这恰是环境相对轨迹的核心优势）；任务难度分布可能被原始轨迹来源偏置。
点评与适用范围
做 code agent 后训练数据/环境的团队可直接复用该框架或其产出语料。『环境即资产』的观点对 agent RL 基建规划很有启发；落地需要轨迹来源和沙箱执行基建，难度中等。
HarnessDev: Can LLMs Create and Evolve Their Own Agent Harness?
arXiv:2609.01437
创新点
把 agent 评测的对象从任务输出移到可运行的基础设施本身：HarnessDev 要求 LLM 从最小种子和少量样例出发创建完整的 agent harness（Creation 阶段），再利用下游执行反馈迭代改进它（Evolution 阶段），最后从能力（held-out 基准任务成功率）和效率（执行 token 成本）两个维度评测所产 harness。这是对『模型能否自举自己的脚手架』这一未探索问题的首个系统性基准。
结论
生成的 harness 在代码、搜索与研究类任务上仍明显落后于人类工程化的成熟参考实现，但在写作和 ML 实验类任务上已能匹配甚至超过参考实现，且执行成本差异巨大。Evolution 带来的提升不稳定、对 held-out 任务只部分迁移；固定运行时模型的实验进一步表明增益强依赖于执行 harness 的模型，跨模型迁移有限。
结论支撑
评测规模大且设计严谨：6 个 creator LLM、4 个领域、5 个下游基准共 2207 个实例，评估任务对开发阶段隐藏，避免过拟合开发集。能力与效率双指标、加固定 runtime 模型的消融，结论证据链比较完整。
局限性
结论依赖所选的人类参考 harness 和下游基准集合，换个参照系结论强度可能变化；Evolution 阶段的迭代预算和反馈形式会显著影响结果，只代表一种设定；『写作和 ML 实验上已匹配人类 harness』可能反映这些领域参考 harness 本身投入不足。
点评与适用范围
对做 agent 基础设施和自进化系统的团队是重要参考：它给出了 harness 自动生成当前的能力边界地图。短期实用价值在于提示哪些领域可以直接用 LLM 生成轻量 harness（写作、ML 实验），哪些仍需人工工程。
Aspire: Can Models Self-Evolve from Vague Goals?
arXiv:2608.31111
创新点
把自进化研究的起点从『人类给定任务和指标』推进到『只给模糊的自然语言能力目标』（如『成为更好的物理学家』），下游评测任务完全隐藏，agent 必须自己操作化目标：选择数据和更新方法、构造训练与验证信号、决定何时评估。ASPIRE 在统一交互环境中同时支持模型权重进化和 agent harness 进化，用 520 条专家编写的隐藏题目跨 6 个目标评测。
结论
模糊目标会把搜索努力重定向到目标理解上。当前 agent 虽能完整跑通训练和 harness 编辑循环，但权重层面的收益稀少且不稳定，最强进化出的 harness 仍低于人工工程的 Qwen-Agent 参考。agent 常在不匹配的数据上训练、轻信狭窄的自评估，导致局部增益无法迁移到隐藏评测，持续搜索和训练甚至会抹掉已有改进。
结论支撑
隐藏专家评测集（520 题、6 目标）有效隔离了自评估偏差，『局部增益不迁移』『继续训练抹掉改进』等负面结论正是靠这套设计暴露出来的，实验设计直指当前自进化叙事的软肋，可信度高。
局限性
仅 6 个目标、520 题，目标多样性有限；结论基于当前一代 agent，『不能从模糊目标自进化』是现状描述而非原理性上限；权重进化所用的训练方法和预算设定会显著影响结论；模糊目标的操作化质量缺乏自动度量，分析多为定性。
点评与适用范围
做 self-evolving agent、自动机器学习和大模型自主改进的团队必读——它系统性地证伪了『给个目标就能自我提升』的乐观叙事，并指出了失败模式（数据错配、自评估过窄）。研究价值大于直接落地价值。
EarlyEval: Cheaper Agent Evaluation via Early Outcome Prediction
arXiv:2609.02783
创新点
提出 agent 评测降本的新维度——任务内早停：agent 的最终成败往往在其中间行为中早已显现。EarlyEval 用 LightGBM 训练一对成功/失败分类器（基于行为、文本和参考解特征），当任一分类器越过校准置信阈值即终止该次运行，与既有的 benchmark distillation（减少任务数）正交互补。
结论
在 SWE-bench Verified、TerminalBench、Toolathlon 三个 benchmark 上，EarlyEval 可消除 13%–26% 的 agent steps、最多 44.1% 的输入 token 和 29.4% 的输出 token，预测准确率 89%–97%，而对每个 agent 的 resolve rate 扰动平均仅 1–2 个百分点。
结论支撑
在三个异构 agentic benchmark 上以实际 token/step 节省与 resolve rate 偏差为指标做了端到端验证，指标选择直接对应“省钱”与“保真”两个目标，实验设计务实合理。轻量分类器的 per-step 开销可忽略。
局限性
分类器需要针对每个 benchmark/特征分布训练，迁移到新 agent 框架或新任务时特征有效性与校准可能漂移；对“前期徘徊、后期翻盘”型任务，早停可能系统性误杀。1–2 点的 resolve rate 扰动在接近饱和的排行榜对比中仍可能改变排名。
点评与适用范围
对高频迭代 agent 的团队（尤其跑 SWE-bench 类昂贵评测的）非常实用：实现简单（LightGBM + 特征工程）、收益即时，适合作为内部研发循环中的“粗筛”环节，正式发榜仍建议全量跑。落地难度低。
Lucida: Parse, Generate, and Place for Composable Real-to-Sim Scene Modeling
arXiv:2608.30821
创新点
沿用 parse-generate-place 三段式管线但重新分配各阶段的信息需求：parse 阶段将视频解析为携带多视角证据的场景图，generate 阶段基于证据为每个实例生成完整资产，place 阶段提出 GizmoAct——一个将物体摆放建模为多轮 GUI 交互的 VLM 策略，闭环操控 gizmo 并自行判断对齐完成，把精度要求从管线入口推迟到末端闭环达成。
结论
在场景级 3D 检测、物体位姿估计和场景重建三项任务上显著提升：R2S-Scene 上 mAP 较 Boxer 提升 69%，CA-1M 上 ADD-SB@0.05 从 57.8% 升至 83.4%，场景 F-Score 从 SAM3D 的 0.794 升至 0.924。
结论支撑
在三个不同任务和多个数据集上与 Boxer、SAM3D 等强基线对比，指标覆盖检测、位姿与重建三个层次，数字提升幅度大且一致。GizmoAct 的闭环 GUI 交互设计是对“一次性位姿回归”的实质性范式替换。
局限性
闭环 VLM 摆放的推理成本与延迟未报告，多轮 GUI 交互在大规模场景上的耗时可能显著；实验限于室内场景，对室外或动态场景的泛化未知。资产生成质量依赖底层生成模型，透明/反光等难材质的处理未讨论。
点评与适用范围
对做具身仿真、real-to-sim 数字孪生的团队有直接借鉴意义：把对齐问题交给 VLM agent 闭环操作而非一次性回归，是一个可迁移的思路。落地需要较强 VLM 与 3D 工具链工程能力，整体管线偏重。
DART-SD: Diamond-topology Aware Retrieval and Tuning for Self-Distillation of Multi-Turn Tool-Calling Agents
arXiv:2608.18524
创新点
指出多轮 tool-calling 中顺序无关子目标的解空间构成组合 diamond 格，全长轨迹模仿会造成“拓扑坍缩”、无差别惩罚合法替代路径。DART-SD 将执行过程建模为收敛的 Interaction-State Transition Graph，自主 rollout 中识别 Critical Topological Breakpoint 并检索成功支撑的恢复参考，再通过 CTB 引导的局部化自蒸馏只在恢复步骤上计算 loss、保护合法推理前缀免受破坏性梯度更新。
结论
在复杂多轮 tool-calling benchmark 上显著优于传统全轨迹模仿基线，验证了“拓扑引导的局部纠错”优于“全局强制模仿”的范式。
结论支撑
以 ISTG 建模 + CTB 定位 + 局部 loss 的消融式框架在多个多轮工具调用 benchmark 上对比全轨迹基线。但 abstract 未给出具体数字与所用模型规模，证据颗粒度偏粗。
局限性
CTB 的识别依赖对成败路径的拓扑建模，在开放式、状态难以离散化的 agent 环境中图构建可能不稳定；恢复参考的检索质量依赖已有成功轨迹库，冷启动场景受限。缺少数字与规模信息，难以评估收益幅度与成本。
点评与适用范围
对训练 tool-calling / agent 模型的团队有方法论启发：loss 只打在先错点后的恢复段、保护正确前缀，这个思路实现门槛低，可与现有 SFT/拒绝采样管线叠加。但论文披露信息偏少，建议等代码或详版结果再决定是否投入复现。
Agentic Artifact Creation: Systems, Evaluation, Principles, and Opportunities
arXiv:2608.28122
创新点
一篇系统综述，定义了"agentic artifact creation"：AI 系统实质性地构建/修改交付物、且中间观测会重定向后续工作的有状态构建过程。提出功能三元组——制品的可操作表示、构建策略、运行时验证反馈——作为分析框架，调研了截至 2026-08-20 的 259 篇工作（230 个系统 + 29 个 benchmark），横跨六类制品家族。
结论
跨家族的分析发现：构建难度不仅取决于模态，更取决于决策耦合程度和失败是否在可修复时可见；分解能降低局部复杂度但增加协调与重组成本；当 learned judge 与生成器共享偏好或盲区时几乎不提供独立证据。作者提出了保持承诺与责任显式化、把反馈转化为定向修复、变更后重验证受影响状态等设计原则。
结论支撑
259 篇文献的大规模结构化调研，把应用场景与评估实践作为独立维度分别分析，并维护开源 paper list。对评估方法论的批判（judge 与 generator 同源问题）有明确的逻辑论证和文献支撑。
局限性
综述性质决定了没有原创实验验证；设计原则偏概念层面，缺少可操作的实现指导。截止 2026 年 8 月的文献覆盖在 agent 领域迭代极快的背景下会迅速过时；六类制品家族的划分可能遗漏新兴形态。
点评与适用范围
适合构建 agent 产品（代码生成、文档生成、设计工具等）的团队作为设计参考，尤其是评估体系设计——"judge 独立性"的警告对用 LLM-as-judge 的团队很实用。作为入门 map 和 design checklist 价值高，零落地成本。
UI-Venus-2 Technical Report
arXiv:2609.00028
创新点
UI-Venus-2 是面向真实部署的通用 GUI agent 基座，覆盖 mobile/web/desktop 三端，通过统一闭环 reasoning-action 框架运作。核心贡献是三个维度的联合 scaling：环境（170+ 多语言 App 和原生桌面 OS）、任务（deep-research pipeline 生成函数级 grounded 指令）、验证（trace 级+样本级评估器，视觉关键点+多模型投票保证 RL 奖励可靠），并集成安全机制控制高危操作。
结论
论文定位为技术报告，提供"有能力、高效、开源"的 GUI agent 基座，推动领域向更可泛化、可验证、自反思的方向发展。abstract 未给出具体 benchmark 数字，主要论断是环境覆盖、任务构造、奖励验证三者的联合 scaling 是 GUI agent 从 benchmark 走向实用的关键。
结论支撑
支撑主要来自大规模工程体系：170+ 真实 App 环境、函数级任务构造 pipeline、双层奖励验证体系。RL 奖励可靠性通过视觉关键点和多模型投票保障，这是对 GUI agent 训练中 reward hacking 问题的务实回应。但缺少 abstract 层面的量化对比，说服力依赖正文数据。
局限性

🔴 重点精读Does On-Policy Distillation Really Distill? From Noisy Teacher to Self-Improvement
arXiv:2608.31046
创新点
对 on-policy distillation (OPD) 的监督信号做了定量“解剖”：发现 teacher 对 student 生成的 off-policy 轨迹打分时噪声很大，且噪声随 teacher 规模增大而增多。进一步发现 OPD 的收益集中在低 log-probability token 上，用固定的负 advantage 替代 teacher 打分即可达到同等效果，据此提出完全无需 teacher 的 On-Policy Self-Adaptation (OPSA)，用 entropy 自适应的负 advantage 抑制长尾 token。
结论
核心结论颇为颠覆：OPD 的提升很大程度上并非来自“蒸馏知识”，而是来自抑制低概率 token，teacher 提供的监督并非必要。OPSA 在 Qwen3-1.7B 上 AIME24 Avg@32 提升 35.41 分（相对 +263%），三个 benchmark 上 Pass@32 翻倍以上，且比 OPD 在 AIME24 Avg@32 上还高 16.77 分。
结论支撑
作者先量化 OPD 训练中的 teacher 噪声并做噪声保留/移除对照，证明 student 对噪声不敏感；再通过“固定负 advantage 与 teacher advantage 等效”的消融定位收益来源。OPSA 在多个模型家族和任务上做了广泛实验，实验链条完整、对照设计有说服力。
局限性
核心实验基于 1.7B 级别小模型和数学推理 benchmark（AIME 等），结论能否推广到更大模型、代码/Agent 等非数学任务尚未验证。AIME 类评测方差较大，Avg@32 虽缓解但未完全消除；“蒸馏无用”的强结论可能只适用于 teacher 与 student 能力差距较小的场景。
点评与适用范围
对做推理模型后训练的团队很有参考价值：若结论成立，on-policy 蒸馏的成本（大 teacher 在线打分）可被几乎零成本的 entropy 自适应负 advantage 替代，工程落地极易。建议在自家任务上先小规模复现“固定负 advantage”对照，再决定是否替换现有蒸馏管线。
推荐理由
对 on-policy distillation 机制的颠覆性解释 + 免 teacher 的 OPSA 方法，可能改变推理模型后训练的成本结构，值得精读并复现。
